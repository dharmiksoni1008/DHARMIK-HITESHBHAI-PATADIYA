PowerShell cURL test guide — expected outcomes, not an execution transcript
==========================================================================
Run from inventory-practice in Windows PowerShell. Use curl.exe (not the old
PowerShell curl alias). JSON is sent with --data-binary from UTF-8 files, avoiding
PowerShell/native argument quoting differences. Do not add -f: 4xx/5xx are expected.
-i prints response status/headers. All normal requests use 3000; direct requests
below are intentional access-control probes. Do not disclose keys in screenshots.

PREPARATION (do not run against valuable inventory):
1. Stop all three servers using Ctrl+C in their own terminals. Keep your .env safe.
2. Run: node tests/reset-data.js
   This resets ONLY .scratch/manual/products.json and stock.json to [] after asking
   you to stop services in this guide. It never modifies data/*.json.
3. In EACH of the three server terminals set:
   $env:DATA_DIR = '.scratch/manual'
   Then run npm run products, npm run stock, npm run gateway respectively.
   Commands must run from the project directory, with your configured .env.
4. In this FOURTH cURL terminal, enter the SAME admin key you configured in .env:
   $admin = [System.Net.NetworkCredential]::new('', (Read-Host 'Admin key' -AsSecureString)).Password
   $base = 'http://127.0.0.1:3000'
   This variable is local to this terminal; it is not written into the guide.
   Command arguments can be visible to other users of this computer; local demo only.
5. Run P, N, then E tests in order. Do not run tests concurrently. If interrupted,
   stop servers, reset, restart, and begin again. Tests using damaged storage,
   stopped servers or the slow fixture have explicit restoration steps.
